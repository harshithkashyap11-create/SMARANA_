## Project rules

- Permissions: explicit IsAuthenticated on new endpoints; patient selectors scope active assignments. Check-in creation is caregiver-only, sync replies are owned by the patient, exports are caregiver/doctor-only. Wrong role and foreign patient tests pass.
- Audit: check-in request/reply, preference changes and exports append audit events; baseline uses existing audited clinical write service.
- Offline: CheckInResponse inherits UUID/device timestamp/idempotency fields. Only `checkin_response` joins the intended push allowlist. Incremental pull and account-scoped metadata preserve pending local answers; server reply replay is idempotent.
- Patient copy: new copy uses aligned English/Assamese/Bengali keys, supportive answers and hints; no patient scores/levels or diagnosis. Native-language editorial review remains the existing publication requirement.
- Design: theme tokens, 64px patient controls, fixed navigation, large-font grid/spacing fixes and focus-managed dialogs. Both-theme screen and overlay checks pass.
- Tests: no xfail, catch-all swallowed errors or weakened assertions. Real-backend test skips only without its explicit backend environment; CI runs it with that environment. Role assertions now reflect the implemented portals and mocked fixtures match pagination.
- Migrations: two explicit migrations; dry-run detects no missing migration. Secrets: only existing public demo credentials in tests; no new secret.
- Diagnosis: descriptive tracking disclaimer included in reports and portal; no generated clinical conclusion.
